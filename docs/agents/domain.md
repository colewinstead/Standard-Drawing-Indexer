# Domain docs

This repo uses a single-context layout: GLOSSARY.md at the root
and architecture decision records under docs/adr/.

Before exploring, read the glossary and ADRs relevant to the task.
If they are absent, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

Use the glossary's vocabulary in issues, code, tests, and proposals.
Flag conflicts with existing ADRs explicitly before proposing changes.
